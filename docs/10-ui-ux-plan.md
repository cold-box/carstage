# CarStage UI/UX 기획

- 작성일: 2026-10-24
- 목적: 기능은 다 들어갔지만 화면이 기능 목록처럼 보입니다. 무대 앱다운 분위기와 차 안에서 읽기 쉬운 화면을 정하고, PR 단위로 넣습니다.
- 기준: [Pleos Connect UI Design Guide](https://document.pleos.ai/en/docs/connect/guide/docs-design/Introduction/intro), [Design Considering Driving Safety](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline), [App Structure and Behavior Model](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-planning-guide/app-structure-screen-model), [Typography](https://document.pleos.ai/en/docs/connect/guide/docs-design/foundations/typography)

## 1. 지금 화면의 문제

2026-10-24 에뮬레이터 화면(무대가 열려 결과 카드와 "이어서 부를까요?"가 함께 보이는 상태)을 기준으로 봤습니다.

| 문제 | 지금 모습 | 왜 문제인가 |
|---|---|---|
| 무대 분위기가 없음 | 단색 어두운 배경, Material 기본 보라 버튼, 제목 "CarStage" 글자 하나 | 차가 노래에 반응하는 앱인데 화면은 설정 앱처럼 보입니다 |
| 화면이 차 조명과 따로 놂 | 조명 색은 왼쪽 실내 그림에만 보이고, 오른쪽 조작 영역은 늘 같은 색 | "차와 화면이 함께 반응한다"는 핵심 경험이 화면에서 약해집니다 |
| 정보 위계가 약함 | 상태 문구, 카드, 버튼 세 개, 안내가 비슷한 무게로 세로로 쌓임 | 운전자는 1~2초 안에 상황을 파악해야 합니다(Glanceability). 지금은 무엇을 먼저 봐야 할지 알기 어렵습니다 |
| 글자가 기준보다 작음 | 결과 카드의 세부 점수·차례 안내 16sp, 글자 버튼("확인", "괜찮아요", "다시 대결") 22sp | Pleos 글자 체계의 가장 작은 단계는 Label 20, Body 26입니다(아래 2장). 이 화면은 160 dpi라 1sp가 1px입니다 |
| 상태마다 화면이 비슷함 | 무대 닫힘, 노래 중, 피날레, 대결, 충전 질문이 같은 틀에 카드만 바뀜 | 지금 무슨 일이 일어나는지(듣는 중인지, 점수를 매기는 중인지) 화면만 봐서는 모릅니다 |
| 안내가 모두 오류 색 | "충전이 끝나서 마지막 곡으로 무대를 마쳤어요" 같은 정보도 빨간 글씨 | 빨강은 오류와 위험에만 써야 합니다. 정보와 오류가 구분되지 않습니다 |
| 개발용 표시가 보임 | 실내 그림 아래 "앰비언트 켜짐 · 밝기 50% · #FFFFFF", 오른쪽 위 "개발자 Lab" | 사용자에게 의미 없는 값입니다. Lab 버튼은 개발 빌드에만 있습니다 |
| 마이크가 켜졌는지 앱 안에서 안 보임 | 상단 상태 표시줄의 초록 마이크 아이콘뿐 | 기획 원칙은 "마이크는 노래하는 동안에만 켜고 화면에 켜짐 상태를 표시"입니다([04](04-karaoke-plan-v2.md) 사업화 리스크) |
| 가로 두 칸만 고려함 | 실내 그림과 조작 영역을 좌우로 나눈 한 가지 배치 | Pleos는 앱을 세로 한 칸이나 가로 두 칸에 띄웁니다. 세로 한 칸이면 지금 배치가 깨집니다 |

## 2. 지켜야 할 기준

### Pleos 원칙 (공식 가이드)

- **한눈에 보기:** 운전자가 1~2초 안에 정보를 파악할 수 있게 꼭 필요한 정보만 둡니다. 입력에 대한 반응은 0.25초 안에 보여 주고, 오래 걸리면 처리 중이라고 표시합니다.
- **대비:** 아이콘, 글자, 그림은 배경과 4.5:1 이상의 대비를 둡니다. 중요한 정보는 대비를 강하게 하되 색을 많이 쓰지 않습니다.
- **글:** 한 문장은 3줄을 넘지 않고, 긴 글 대신 아이콘과 짧은 문장을 씁니다. 핵심 정보는 높이 4 mm 이상, 일반 글자는 3 mm 이상입니다.
- **아이콘과 반응:** 널리 알려진 아이콘에 글자 라벨을 함께 붙이고, 터치하면 진동이나 소리로 반응합니다. 2026-11-01: 제품 화면의 모든 버튼, 스위치, 선택, 목록 줄, 안내 펼치기가 시스템 클릭 소리와 진동(화면이 진동을 지원하면)을 냅니다(`ui/TapFeedback`). 둘 다 차의 터치 소리·진동 설정을 따릅니다.
- **조작:** 한 손으로 쉽게 조작할 수 있어야 하고, 자주 쓰는 기능은 첫 화면 위쪽에 둡니다. 여러 단계 메뉴와 드롭다운을 피하고, 음성(Gleo)을 적극적으로 씁니다.
- **움직임:** 주행 중에는 운전자의 시선을 끄는 애니메이션과 영상을 쓰지 않습니다. CarStage는 정차 중에만 무대를 열고 주행이 시작되면 연출을 숨기므로, 무대 화면의 움직임은 정차 중에만 보입니다.
- **주간·야간:** 밝기와 대비를 주간·야간에 맞춥니다.
- **창 크기:** 앱은 세로 한 칸(다른 앱과 나란히)이나 가로 두 칸으로 뜹니다. 두 모양 모두 핵심 기능이 보이게 하고, 가로에서는 넓은 자리에 추가 정보를 둡니다. 크기가 바뀌어도 화면(액티비티)을 다시 만들지 않으므로 무대와 화면 상태는 그대로입니다(Pleos 앱 심사 "Display Compatibility", 2026-11-01). 두 칸과 한 칸 사이를 넘나들 때만 오른쪽 조작 부분을 새로 그려, 펼친 안내가 다시 접히고 노래 목록이 맨 위로 갑니다.

### 글자 체계 (Pleos Typography, 크기와 굵기)

| 단계 | 크기 | 굵기(Pleos → 앱) | 줄 높이(앱이 정함) | 쓰는 곳 |
|---|---|---|---|---|
| Headline Large / Medium / Small | 60 / 56 / 48 | Extra Bold, Bold → Bold | 1.2배 | 흥 점수 숫자, 대결 차례 |
| Title Large / Medium / Small | 40 / 36 / 32 | Extra Bold, Bold, Regular → Bold | 1.3배 | 상태 문구("노래를 불러 보세요"), 등급 문구, 승자 발표, 큰 버튼 글자 |
| Body Large / Medium / Small | 30 / 28 / 26 | Strong, Normal → Normal | 1.4배 | 안내 문장, 보조 버튼 글자, 카드 머리말 |
| Label Medium / Small | 24 / 20 | Normal → Normal | 1.4배 | 세부 점수, 긴 설명, 실내 그림의 좌석 이름, 플레이어의 시간. Label Small(20)은 제품 화면에 쓰지 않습니다(아래) |

- 제품 화면의 글자는 24 이상으로 씁니다. Android 차량 앱 품질 기준(UX-3)이 24 이상을 요구하므로 2026-11-01에 좌석 이름과 플레이어 시간을 Label Small(20)에서 Label Medium(24)으로 올렸습니다.
- 시스템 글꼴은 Asta Sans입니다. 앱은 따로 글꼴을 넣지 않고 시스템 글꼴을 씁니다(일관성).
- 이 화면은 160 dpi라 위 숫자를 그대로 sp로 씁니다. 다른 밀도의 차에서도 sp로 쓰면 비율이 유지됩니다.
- Pleos Typography 페이지는 크기와 굵기만 그림으로 보여 주고 줄 높이는 없습니다(2026-10-25 확인). 줄 높이는 앱이 위처럼 정했습니다.
- 줄은 단어 사이에서만 바꿉니다("끝났는데"가 "끝 / 났는데"로 나뉘지 않게). Android 13 이상이 한국어 글자에 대해 이렇게 나누므로, 시스템 언어와 상관없이 글자를 한국어로 표시합니다. 에뮬레이터(Android 14)에서 확인했고, Android 12 이하인 차는 음절 사이에서 나뉩니다([05](05-emulator-findings.md) "화면 디자인 토큰 확인").

### 터치 크기 (Android Automotive 기준, Pleos 가이드가 따름)

- 터치 영역은 76×76dp 이상, 터치 영역 사이는 23dp 이상입니다([Android for Cars 디자인 원칙](https://docs.partner.android.com/drivingux/foundations/design-principles)). Pleos 가이드는 "큰 터치 영역"을 요구하고 버튼 크기는 컴포넌트 가이드를 따르라고 합니다. 정확한 Pleos 값은 아직 확인하지 못했습니다.

## 3. 디자인 방향

### 콘셉트: "차가 무대가 된다"

화면은 무대 옆의 조명판입니다. 실내 조명과 화면이 같은 색으로 함께 숨 쉬어서, 탑승자는 "차 전체가 내 노래에 반응한다"고 느낍니다.

- **화면이 조명을 따라감:** 무대가 열리면 배경 가장자리에 지금 앰비언트 조명 색의 부드러운 빛(글로우)을 깝니다. 목소리가 커지면 빛이 밝아지고, 피날레에서는 등급 색으로 바뀝니다. 실내 그림 하나에만 있던 반응이 화면 전체로 넓어집니다.
- **어두운 무대 + 한 가지 빛:** 배경은 거의 검정에 가까운 짙은 남색, 글자는 흰색 계열, 강조는 그때의 조명 색 하나만 씁니다. 색을 여러 개 쓰지 않는다는 Pleos 원칙과도 맞습니다.
- **큰 숫자와 짧은 말:** 점수, 차례, 상태는 크게 쓰고 문장은 한 줄로 줄입니다.
- **깜빡임 없음:** 빛은 0.5초 이상에 걸쳐 천천히 바뀝니다(5장 "움직임"과 같음). 대결 발표의 좌우 번갈이는 이미 광과민 기준 아래로 맞춰 두었습니다([04](04-karaoke-plan-v2.md) 기능 2).

### 두 가지 시안 (결정이 필요함, 9장)

| | A. 콘서트 조명판 (추천) | B. 차 내장 UI처럼 절제 |
|---|---|---|
| 분위기 | 무대 조명 같은 글로우, 큰 숫자, 점수 카운트업 | Pleos 시스템 화면과 같은 회색 카드, 작은 포인트 색 |
| 장점 | 화면에서 "차가 반응한다"가 바로 보임 | 시스템과 이질감이 적고 만들기 쉬움 |
| 위험 | 과하면 가볍게 보임. 정차 중에만 보여야 함 | 지금과 크게 다르지 않아 보일 수 있음 |
| 대응 | 무대가 닫힌 대기 화면은 B처럼 절제하고, 무대가 열리면 A로 바뀜 | |

추천은 "대기 화면은 B, 무대가 열리면 A"입니다. 평소에는 차의 다른 앱처럼 차분하고, 노래가 시작되면 무대로 바뀌는 대비가 그 자체로 연출이 됩니다.

## 4. 화면 상태와 배치

한 화면 안에서 상태만 바뀝니다(메뉴 깊이 없음). 상태마다 "지금 무슨 일인지"를 첫 줄에서 바로 알 수 있게 합니다.

| 상태 | 첫 줄(Title) | 가운데 | 아래(버튼) |
|---|---|---|---|
| 대기, 음악 없음 | "음악 앱에서 노래를 틀어 주세요" | 음성 힌트: "Gleo에게 '노래 무대 열어줘'라고 말해 보세요"(마이크가 허용되지 않았으면 마이크를 쓰는 이유, 7장) | 주 버튼 "노래 시작" |
| 대기, 음악 감지 | "노래가 나오고 있어요" | 같은 음성 힌트 | 주 버튼 "무대 열기" |
| 대기, 노래 목록 | "부를 노래를 골라 주세요" | 차의 음악 앱 곡 목록(아래 "노래 목록"), 곡을 누르면 재생과 무대 열기 | 주 버튼 "노래 시작" |
| 이어서 부르기 제안 | "통화가 끝났어요" / "다시 정차했어요" | "이어서 부를까요?" | 주 버튼 "이어서 부르기", 글자 버튼 "괜찮아요" |
| 노래 중 | "듣고 있어요" + 마이크 표시(상태 줄, 2번 PR) | 목소리 반응 미터(반주보다 튀어나온 만큼 차오름), 환호하면 반짝임 | 보조 버튼 "곡 끝내기", "대결", 주 버튼 "무대 닫기" |
| 두 분 착석 | "두 분이 타셨네요" | 대결 소개 한 줄 | "대결 시작"을 강조 버튼으로(주 버튼은 "무대 닫기" 그대로, 1번 PR) |
| 피날레·결과 | 등급 문구("흥이 올랐어요") | 점수 숫자(Headline Large, 등급 색, 카운트업), 네 항목 막대(참여·열기·호응·완창) | "확인" |
| 대결 차례 | "운전석 차례" (파랑) | 좌우 점수판(운전석 \| 조수석), 차례인 쪽 강조 | "곡 끝내기" |
| 대결 발표 | "결과를 발표하겠습니다" | 좌우 점수판이 번갈아 빛남 → 승자 쪽 확대 | 없음(발표 중에는 터치를 받지 않음) |
| 대결 결과 | "승자는 조수석!" (빨강) | 두 점수, "다음 곡에서 역전해 보세요!" | "다시 대결", "확인" |
| 충전 끝 질문 | "충전이 끝났어요" | "마지막 곡으로 마무리할까요?" | "마지막 곡으로", "계속 부르기" |

### 노래 목록 (2026-10-31 구현)

차의 음악 앱이 MBS로 내주는 곡 목록입니다(`home/SongListCard`, 기능은 [07](07-convenience-features.md) "노래 목록").

- 자리
    - 무대가 닫혀 있음: 오른쪽 칸의 첫 줄("부를 노래를 골라 주세요")과 주 버튼 "노래 시작" 사이. "이어서 부를까요?"가 떠 있으면 숨김
    - 무대가 열려 있음: 미니 플레이어 오른쪽 끝의 목록 버튼(글자 없는 목록 아이콘, 열면 강조 바탕) → 미니 플레이어 바로 아래에 열고 닫음. 왼쪽 칸이면 실내 그림이 그만큼 작아짐. 무대를 닫으면 접힘
    - 세로 한 칸: 같은 카드를 같은 순서로 쌓음. 목록은 최대 440dp(약 5줄)에서 스크롤하므로 칸을 넘지 않고, 실내 그림이 먼저 접힘(`ColumnPlan`)
- 모양: `HomeCard` 틀(폭 560dp, 카드 색)

### 안내 종류

안내를 띄우는 곳마다 종류를 함께 정합니다(`NoticeTone`). 처음 정한 나눔은 이렇습니다(2026-10-25).

| 종류 | 뜻 | 예 |
|---|---|---|
| 정보(파랑) | 앱이 한 일, 하는 중인 일 | 전화가 와서 멈춤, 주행을 시작하거나 차량이 앱 사용을 제한해서 멈춤, 충전이 끝나 마침, 밤 조명 낮춤, 지난 무대의 설정을 되돌림, 되돌리는 중이거나 차 연결을 기다림 |
| 주의(노랑) | 사용자가 알아 두거나 해야 할 일 | 정차·통화·차량 제한으로 열 수 없음, 마이크 권한·마이크 무음, 배터리 부족, 공회전, 차에 연결하지 못함, 차가 제어를 허용하지 않음, 정차하면 되돌림, 아직 되돌리지 못해 열 수 없음, 이 차에서 곡 정보 설정을 열 수 없음 |
| 오류(빨강) | 잘못된 일 | 되돌리지 못함, 지난 무대 기록을 읽지 못함, 마이크가 끊기거나 열리지 않음, 문제가 생겨 닫음, 무대를 열거나 닫지 못함, 대결 시작 실패, 기어를 읽지 못함 |

- 멈춘 이유와 되돌리지 못한 설정을 한 줄로 알릴 때처럼 여러 안내가 한 줄에 있으면, 가장 심각한 종류의 색으로 보여 줍니다.
- 종류를 받지 못한 글만 있는 줄은 오류로 봅니다(안내가 모두 빨강이던 때와 같게).
- 한 안내가 다른 종류의 더 긴 안내 안에 그대로 들어 있으면 색이 잘못 정해지므로, 짧은 안내를 새로 만들 때 기존 안내와 겹치지 않게 합니다. 같은 글에는 늘 같은 종류를 줍니다.

### 글자와 버튼

- 2장의 Pleos 글자 체계를 Compose `Typography`의 같은 이름 자리에 옮겼습니다(`PleosTypography`). Material의 Display 자리는 Headline 크기, Label Large 자리(Material 버튼의 기본 글자)는 Body Large 크기로 채워 체계 밖의 작은 글자가 나오지 않게 했습니다. 개발자 Lab은 진단 줄이 많아 Material 기본 크기를 그대로 씁니다.
- 주 버튼은 한 화면에 하나만 두고, `#C8309F`로 채웁니다(높이 96dp, 폭 400dp, `PrimaryButton`). 보조 버튼은 높이 76dp, 폭 400dp에 외곽선 또는 강조 바탕입니다(`SecondaryButton`). 카드 안의 선택도 주 버튼을 쓰지 않습니다.
- 글자 버튼은 Body Medium(28), 터치 영역 76dp 이상입니다(`QuietButton`).
- 화면 코드에는 글자 크기 숫자나 색 값을 직접 쓰지 않고 `StageColors`, `StageSizes`, `MaterialTheme.typography`, 실내 그림(`CabinView`)의 `CabinColors`만 씁니다. 그림 색은 2026-10-27에 `CabinColors`로 옮겼습니다(8장 "5번 PR 구현").
- 오른쪽 칸은 가운데에 모아 두고, 카드 두 장과 여러 안내가 쌓여 높이를 넘으면 그때만 스크롤됩니다.
- 터치하면 짧은 진동(지원하는 차) 또는 시스템 클릭 소리로 반응합니다.

### 아이콘

- 마이크(듣는 중), 대결(두 사람), 곡 끝(체크 깃발), 무대(조명), 충전(번개)을 Material Symbols에서 고르고, 항상 글자 라벨을 함께 씁니다.
- 실내 상태 아이콘(`CabinStatus`, 6장)은 예외로 글자 라벨 없이 직접 그립니다(2026-10-31, 사용자 요청). 2026-11-01: 타일 다섯 개를 상태 알약 하나로 바꿨습니다(사용자가 고른 시안). 늘 보이는 것은 앰비언트 색 점과 밝기 바뿐이고, 나머지는 켜진 동안만 붙습니다. 화면 낭독기는 같은 값을 문장(`CabinLook.captions`)으로 읽습니다.
- 안내 줄의 종류 아이콘(정보·주의·오류)은 아이콘 라이브러리 없이 직접 그립니다(미니 플레이어의 재생 기호와 같음, 7장 "안내 문구"). 아이콘은 안내 글과 같은 색이고, 안의 기호는 화면 바탕색이라 대비가 글과 같습니다.

### 움직임

- 상태가 바뀔 때 0.2초 페이드만 씁니다. 화면이 날아다니지 않습니다.
- 점수 숫자는 0에서 점수까지 1초 동안 올라갑니다(정차 중). 2026-11-02부터 노래 중인 무대의 점수 공개가 1.2초 동안 올립니다(아래 "점수 공개").
- 대결 발표에서 승자 칸은 0.6초에 걸쳐 1.08배로 커집니다(4장 표의 "승자 쪽 확대"). 자리를 옮기지 않고 그 칸만 커집니다.
- 안내 줄이 접히거나 펼쳐질 때는 높이가 0.2초에 걸쳐 바뀝니다(7장 "안내 문구"). 가운데 정렬한 칸의 나머지도 그만큼 함께 움직입니다.
- 글로우는 조명 값을 따라 0.5초 이상에 걸쳐 바뀝니다. 깜빡이지 않습니다.
- 무대를 여닫는 동안에는 제목 왼쪽에 원형 진행 표시가 돕니다(노래 목록의 불러오는 중과 같은 색). Pleos 심사 가이드는 버튼 동작이 2초 안에 끝나지 않으면 처리 중임을 보이라고 합니다(2026-11-01).
- 주행이 시작되면 모든 움직임을 멈추고 연출을 숨깁니다(지금도 무대를 닫음).

### 점수 공개 (2026-11-02)

내부 시험에서 곡의 점수가 작은 한 줄("방금 곡 68점 · 흥이 올랐어요")로만 나와, 무대의 정점치고 약했습니다. 노래방 점수 화면과 게임의 결과 연출(등급별로 연출을 다르게 하고 가장 높은 등급만 드물게 축하, 숫자가 멈추는 순간 등급 표시)을 참고해 바꿨습니다(`home/ScoreReveal`).

- 곡의 점수가 나오면 무대 문장과 점수 줄 자리를 점수 공개가 차지합니다. 바뀔 때는 안내 줄처럼 0.2초 동안 페이드하며 높이도 0.2초에 걸쳐 바뀌어, 아래 버튼과 플레이어가 순간 이동하지 않습니다. 위에서부터 곡 제목(음악 앱이 알려 줄 때), 0부터 점수까지 1.2초 동안 올라가는 숫자(Headline Large, 등급 색), 숫자가 멈추면 도장처럼 1.5배에서 제 크기로 내려앉는 등급 말(Title Large: "좋은 출발", "흥이 올랐어요", "흥부자"), 가장 잘한 점(MC가 말하는 것과 같은 문장, `McLines.praise`)입니다.
- 가장 잘한 점을 화면에도 보여 주므로 MC를 껐거나 음악에 묻혀도 읽힙니다. MC는 피날레 박수가 끝난 뒤 점수를 말합니다(기본 등급은 약 2.3초, 좋음·최고 등급은 박수가 길어 약 5초 뒤에 시작해 몇 초 동안 말함). 그래서 공개는 6초 이상, MC가 그 말을 마칠 때까지(`StageMc.busy`) 떠 있고, 길어도 12초에 접습니다.
- 최고 등급(흥부자)만 숫자 둘레에 금색 고리가 0.7초에 걸쳐 퍼졌다가 0.7초에 걸쳐 사라집니다. 고리는 숫자 줄과 그 위아래 간격(8dp) 안의 타원이라 곡 제목이나 등급 말 밑으로 번지지 않습니다. 가운데는 비우고, 가장 밝을 때도 금색 35%라서 숫자 뒤를 지나는 부분에서도 금색 숫자가 4.5:1을 지킵니다(`StageColors.BestRing`, `StageColorsTest`, 처음 정한 50%는 3.2:1이었음). 깜빡이지 않습니다.
- 누르면 바로 최종 점수를 보여 줍니다(터치 피드백 포함). 시스템의 애니메이션이 꺼져 있으면(개발자 옵션의 애니메이션 배율 0) 처음부터 최종 점수입니다.
- 공개가 끝나면 "방금 곡 <점수>점 · <등급 말>" 한 줄로 접히고 무대 문장이 돌아옵니다. 공개가 시작될 때 페이드로 사라지는 한 줄은 이전 곡의 점수를 그대로 보여 주어, 새 점수를 0.2초 먼저 드러내지 않습니다. 숫자는 폭이 같은 숫자 모양(`tnum`)으로 그려 올라가는 동안 좌우로 흔들리지 않습니다. 화면을 떠났다 돌아오면 이미 나온 점수를 다시 공개하지 않습니다. 대결 중에는 대결 카드가 점수를 보여 주므로 쓰지 않습니다.
- 글자 크기와 색은 모두 기존 토큰입니다(Headline Large 60이 가장 큰 글자).

## 6. 실내 시뮬레이터

에뮬레이터는 조명 값을 실제로 바꾸지 않아서, 차가 반응하는 모습은 이 그림으로만 보여 줄 수 있습니다.

- 앰비언트 줄에 색 글로우를 넣어 실제 무드등처럼 번지게 합니다.

- 지금 아래에 있는 값 표시("앰비언트 켜짐 · 밝기 50% · #FFFFFF")는 개발 빌드에서만 보이고, 제품에서는 그림만 남깁니다. 2026-10-31 변경: 글자 대신 상태 아이콘 줄(`CabinStatus`)로 바꿔 모든 빌드에 보입니다. 앰비언트(조명 색 전구와 밝기 링), 독서등(운전석·조수석 등과 빛 원뿔), 시트 통풍(좌석과 물결 3단), 온도(온도계, 낮추면 파랑 ▼, 올리면 따뜻한 색 ▲), 풍량(날개와 단수 점)이고, 연출이 바꾸는 동안 그 색으로 빛나며 타일 테두리가 생깁니다(앰비언트만은 켜져 있으면 늘 그 색). 글자 라벨은 붙이지 않고(사용자 요청), 화면 낭독기는 같은 값을 문장으로 읽습니다.

### 2번 PR 구현 (2026-10-27)

- 상태 줄: 오른쪽 칸 묶음의 맨 위 한 줄(칸은 가운데 정렬이라 카드에 따라 위치가 움직임)에 앱 이름, 마이크 상태, 충전을 함께 둡니다. 무대가 듣는 동안 초록 점과 "듣고 있어요", 다른 앱이 마이크를 잡거나 음소거되어 디지털 무음만 약 3초 이어지면 노랑 점과 "잠시 안 들려요"입니다(`LiveMic.state`, 화면 아래 무음 안내와 같은 신호). 통화가 오면 무대를 닫으므로 통화 중에는 마이크 상태를 보여 주지 않습니다. 충전 중이면 "충전 중 · <잔량>%"가 같은 줄에 붙습니다. 예전의 제목 줄과 충전 줄을 한 줄로 합쳤습니다. 2026-11-01: 줄 끝에 MC 스위치(스피커 아이콘, "MC", 스위치를 합친 높이 76dp의 터치 영역)를 더했습니다([12](12-mc-plan.md) 4장). 같은 날 MC 스위치는 화면 오른쪽 아래 구석의 말풍선 아이콘으로 옮겼습니다([12](12-mc-plan.md) 4장). 세로 한 칸(841dp)에서 무대가 열려 "듣고 있어요"와 "충전 중 · 80%"가 함께 나와도 한 줄(약 710dp)에 들어갑니다([05](05-emulator-findings.md) "MC 끄기 확인"). 그보다 길어지면("잠시 안 들려요", 큰 글자 설정) 스위치를 줄이지 않고 다음 줄로 넘깁니다.
- 반응 미터: 무대가 열린 동안 안내 문구(대결 카드가 있으면 그 카드) 아래, 주 버튼 위에 "목소리" 막대를 둡니다. 반주보다 튀어나온 목소리만큼 차오르고, 조명과 같은 빠르기로 움직입니다(프레임마다 남은 차이의 50%로 오르고 8%로 내림, 초당 약 23프레임이라 거의 다 차는 데 약 0.2초, 가득 찬 데서 비는 데 약 2초, `VoiceMeter`). 색은 지금 앰비언트 조명 색이고, 막대 바탕(`Track`)과 4.5:1이 될 때까지 흰색 쪽으로 밝힙니다(`StageColors.meter`, 파랑·보라 조명도 기준을 지킴). 환호하면 막대가 곧바로 가득 차며 하얗게 밝아졌다가 0.8초에 걸쳐 돌아옵니다(한 번 번쩍임이고 되풀이하지 않음). 막대는 버튼과 같은 폭(400dp)으로 가운데에 맞춥니다. 막대 값은 그릴 때만 읽고 0.02(8dp) 이상 움직일 때만 넘겨, 움직여도 화면의 나머지는 다시 구성하지 않습니다.
- 결과 카드: 점수가 0에서 1초 동안 올라가고, 네 항목(참여·열기·호응·완창)이 막대로 같이 차오릅니다. 숫자와 막대는 등급 색입니다. 카드가 다시 나타나면(Lab에서 돌아올 때 등) 다시 올라갑니다.

### 4번 PR 구현 (2026-10-27)

- 대결 카드 가운데에 좌우 점수판을 둡니다. 왼쪽이 운전석, 오른쪽이 조수석으로 앉은 자리와 같습니다. 칸마다 자리 이름(그쪽 색)과 점수 자리가 있고, 점수 자리는 글자가 바뀌어도 높이가 같아 점수판이 흔들리지 않습니다(값은 `BoardSide`, 그리기는 `DuelCard`).

- 마무리: 승자 조명이 켜지는 순간(발표 시작 약 6초 뒤, 팡파레와 함께) 대결 상태가 "승자 공개"가 되어(`DuelState.winnerShown`, `GlowDirector`가 `DuelAnnouncement.crowned`를 보고 넘김) 제목이 "승자는 조수석!"으로 바뀌고, 가려 둔 점수가 나오고, 승자 칸이 0.6초에 걸쳐 1.08배로 커집니다. 무승부는 두 칸이 모두 빛나고 커지지 않습니다. "다시 대결"과 "확인"은 발표가 끝난 뒤(약 10초)에 나옵니다. 발표 중에 무대를 닫으면 바로 결과로 넘어가 모두 보여 줍니다.
- 칸의 빛은 화면 상태가 바뀌는 것이므로 5장 "움직임"의 0.2초 페이드를 씁니다(가장 짧은 차례 약 0.38초 안에 끝남). 3장의 "0.5초 이상"은 조명을 따라가는 글로우의 규칙입니다. 승자 칸이 커지는 0.6초는 4장 표의 "승자 쪽 확대"로 정한 움직임입니다. 빛나는 칸의 바탕은 그쪽 조명 색 20%를 화면 바탕 위에 겹친 불투명 색(`StageColors.litPanel`)이고, 흰 글자·보조 글자·그쪽 색 글자가 모두 4.5:1 이상입니다(`StageColorsTest`). 테두리는 그쪽 글자 색입니다.

### 5번 PR 구현 (2026-10-27)

- 차 모양: 앞이 위인, 위에서 본 차입니다. 둥근 앞뒤와 사이드미러가 있는 차체, 앞유리와 뒷유리, 대시보드와 송풍구 네 개, 왼쪽 운전대, 가운데 콘솔, 앞좌석 두 개와 뒷좌석을 그립니다. 좌석은 방석, 등받이, 머리받침을 위에서 본 실루엣입니다.
- 앰비언트: 대시보드 뒤 가장자리와 양쪽 문을 따라 줄이 세 개 있습니다. 켜지면 줄 둘레로 빛이 번져 바닥을 물들이고(넓고 옅은 빛과 가깝고 밝은 빛 두 겹, 실내 밖으로는 번지지 않음), 실내 전체도 조명 색으로 옅게 물듭니다. 밝을수록 빛이 세지고 줄 자체가 흰빛을 띱니다(가장 밝을 때 흰색 쪽으로 40%). 꺼지면 어두운 줄만 남습니다.
- 독서등: 앞유리와 지붕이 만나는 곳(그림에서는 앞유리 아래 가장자리, 대시보드 바로 앞)의 등에서 그 좌석으로 따뜻한 빛 원뿔이 퍼지고, 방석 위에 빛 웅덩이가 생깁니다. 대결 발표에서는 원뿔이 좌우로 번갈아 켜져 무대 조명처럼 보입니다. 꺼진 등은 테두리만 보입니다.
- 시트 통풍: 방석 위의 바람 물결입니다. 한 단마다 한 줄씩(3줄까지, 무대가 보내는 가장 높은 단) 늘고, 0.2초에 걸쳐 나타납니다(5장 "움직임"). 발표 마무리에서는 승자 좌석이 독서등과 통풍을 함께 받으므로, 물결을 빛 위에 그리고 좌석 색 테두리를 둘러 빛 웅덩이 위에서도 보이게 했습니다.
- 풍량: 가운데 송풍구 두 곳에서 앞좌석 쪽으로 바람 줄기가 나오고, 한 단 올릴 때마다 길어지며(4단까지) 끝으로 갈수록 옅어집니다. 피날레의 "환호 바람"(한 단 올림)이 이렇게 보입니다. 송풍구 가까이는 대시보드 줄의 번진 빛이 비추는 곳이라, 줄기에 대시보드 색 테두리를 둘렀습니다(테두리도 줄기와 함께 끝으로 갈수록 옅어짐).
- 온도: 좌석 이름 옆에 시작 때와의 차이를 씁니다(예: "조수석 -2°"). 낮추면 파랑, 높이면 노랑 글자입니다(`CabinLook.temperatureChange`).
- 빠르기: 조명(앰비언트, 독서등)은 차에 보낸 값을 그대로 보여 주므로 명령 간격(약 120ms)보다 조금 짧은 0.1초로 따라갑니다. 3장의 "0.5초 이상"은 무대 글로우의 규칙입니다. 통풍과 풍량은 단으로 바뀌므로 5장 "움직임"의 0.2초를 씁니다.
- 색: `ui/Theme.kt`의 `CabinColors`에 있습니다. 차는 화면 바탕과 같은 남색 계열을 한 단계씩 밝혀 상태 표시의 바탕으로 두되, 바닥만 차체보다 어둡게 두어 앰비언트 빛이 보이게 합니다. 상태를 알리는 것(켜지거나 꺼진 독서등, 통풍 물결, 송풍구에서 나오는 곳의 바람, 좌석 이름)은 놓인 곳과 4.5:1 이상이고, 흰 조명이 가장 밝게 비출 때(흰색 15%를 겹친 바탕)도 같습니다(2장 "대비", `StageColorsTest`). 앰비언트 줄은 조명 그 자체라 무대가 보낸 색 그대로입니다. 꺼진 독서등 테두리는 처음 고른 색이 앞유리 위에서 4.0:1, 다음 색이 밝게 비친 대시보드 위에서 3.7:1이라 두 번 밝혔습니다(지금 4.9:1).
- 그리기 비용: 바뀌지 않는 부분(차체와 유리, 바닥과 대시보드, 송풍구, 콘솔, 좌석, 운전대)은 크기가 바뀔 때마다(처음 보일 때, 미니 플레이어가 나타나거나 사라질 때 등) 이미지로 한 번 그려 두고, 앰비언트 빛(실내를 물들이는 빛과 줄 둘레의 번짐)은 흰 마스크로 한 번 만들어 둡니다(이미지가 네 장이던 때 재니 모두 합쳐 한 번에 10~16ms). 프레임마다 이 이미지를 그리고 마스크에 조명 색과 밝기를 입힌 뒤, 앰비언트 줄, 독서등, 통풍, 바람, 좌석 이름만 새로 그립니다. 무대 글로우(3번 PR)처럼 자기 그래픽 레이어에 그려, 그림이 움직여도 화면의 나머지는 다시 기록하지 않습니다. 처음에는 프레임마다 모든 모양을 그렸는데, 녹음 재생 중 앱 CPU가 이 PR 전의 그림보다 코어 하나 기준 약 7%p 높았습니다. 이미지로 바꾼 뒤에는 같은 수준입니다([05](05-emulator-findings.md) "실내 그림 확인").
- 그림 아래의 상태 아이콘 줄은 두 칸 배치에만 보이고 세로 한 칸에서는 숨깁니다(2026-10-31, 값 줄을 대신함).

### 6번 PR 구현 (2026-10-27)

- 언제: 창의 폭(바깥 여백 32dp를 뺀 폭)이 카드 두 장과 두 칸 사이 간격(560 × 2 + 48 = 1168dp)보다 좁으면 한 칸으로 쌓습니다. Pleos 홈에서 앱 자리를 둘로 나누면 CarStage는 841×1210dp가 되어 한 칸이 되고, 나누지 않은 1682×1210dp는 지금처럼 두 칸입니다. 예전에는 한 칸에서도 두 칸을 그대로 좁혀, 오른쪽 칸이 약 370dp가 되고 대결 카드와 버튼이 좁아지며 글자가 여러 줄로 꺾였습니다.
- 순서: 위에서부터 실내 그림, 미니 플레이어(있을 때), 무대 조작(상태 줄, 카드, 안내, 미터, 버튼, 음성 힌트, 안내 줄)입니다. 무대 조작은 두 칸일 때의 오른쪽 칸과 같은 것을 씁니다.
- 실내 그림: 미니 플레이어와 무대 조작이 쓰고 남은 높이를 모두 받습니다. 남은 높이가 360dp(그림 폭 약 220dp)보다 작으면 그림을 접고, 나머지를 가운데에 둡니다(`ColumnPlan`). 무대가 닫혀 있으면 그림이 크게 보이고, 무대가 열리면 작아지며, 결과·대결 카드가 뜨거나 무대가 열린 채 미니 플레이어가 있으면 접힙니다. 그림 아래의 개발용 값 줄은 한 칸에서는 보이지 않습니다(조작을 우선함). 그림의 높이는 무대 조작의 높이를 따르므로, 안내 줄이 생기거나 사라지면 그림도 그만큼 커지거나 작아지고(그때마다 실내 그림의 이미지를 다시 만듦, 5번 PR "그리기 비용"), 남는 높이가 360dp 언저리면 안내 한 줄에 그림이 접혔다 펴질 수 있습니다. 정보 안내가 접히거나 펼쳐질 때도 그만큼 그림의 높이가 바뀝니다(7장 "안내 문구").
- 무대 조작과 미니 플레이어만으로 높이를 넘으면 칸 전체가 스크롤됩니다. 결과 카드가 뜬 열린 무대도 그림을 접으면 한 화면에 들어갔습니다([05](05-emulator-findings.md) "세로 한 칸 확인").
