- 상태: 현재 기준 기획입니다.

## 2차에서 반영한 요청

1. 곡이 끝나면 박수 효과와 조명 반응을 주는 **피날레** 연출
2. 2명이 탔을 때 좌우로 조명이 왔다갔다 하다가 승자를 알려 주는 **발표 모드**
3. 위험해 보이는 사업화 영역을 검토해서 기능을 다듬기

## 중요한 확인 결과: 앰비언트 조명은 좌우 구분이 어려움 (2026-10-21 정정)

처음에는 샘플 앱 코드를 근거로 "조명 API에는 영역 지정이 없다"고 판단했지만, 이 판단은 틀렸습니다. Vehicle SDK 2.3.2의 앰비언트 조명과 독서등 API는 `SeatArea`(좌석별 영역)를 인자로 받습니다. 다만 에뮬레이터에서 지원 영역을 조회해 보니 앰비언트 조명은 실내 전체를 묶은 영역 하나뿐이었습니다. 반면 독서등, 온도, 시트 통풍은 운전석과 조수석을 따로 제어할 수 있습니다. 그래서 "좌우로 왔다갔다"는 독서등, 온도, 시트 통풍, 스피커 좌우 패닝, 화면을 겹쳐서 만들고, 앰비언트 조명은 실내 전체 색으로 씁니다. 자세한 결과는 [05-emulator-findings.md](05-emulator-findings.md)에 있습니다.

## 기능 1. 피날레: 곡이 끝나면 박수와 조명

### 곡 종료 감지

세 가지 방법을 차례로 시도합니다.
1. 음악 앱의 트랙 변경 정보를 받을 수 있으면 그 정보로 판단합니다. 가장 정확하지만, 다른 앱의 재생 정보에 접근할 수 있는지는 확인이 필요합니다.
2. 마이크 소리를 분석해서 노래가 멈추고 트랙 사이 무음이 1초 이상 이어지면 곡이 끝난 것으로 봅니다. (2026-10-23 구현: 기준과 시험 결과는 [09](09-voice-reaction-plan.md) 5장 "곡 종료 감지")
3. 위 두 방법이 실패하면 "끝" 같은 음성 명령이나, 정차 중에는 큰 버튼으로 직접 끝냅니다. (2026-10-23 구현: 화면의 "곡 끝내기" 버튼과 Gleo `FINISH_SONG`)

### 정차 중 연출 순서

2026-10-23 구현: 조명(등급 색으로 세 번 출렁임, "최고"는 독서등 반짝임)과 결과 화면만 넣었습니다. 2026-10-24에 박수 효과음(CC0, README "효과음 출처")을 넣었고, 같은 날 아래 "점수 등급" 표처럼 등급마다 다르게 했습니다. 기본은 짧은 박수(1.6초), 좋음은 박수(4.1초), 최고는 팡파레와 박수를 함께(박수는 0.7 크기로 낮춰 팡파레가 앞에 들림) 냅니다. 표의 환호·휘파람·기립박수 소리와 위 표 "0초"의 환호 효과음은 따로 넣지 않았습니다. 효과음은 오디오 포커스를 일시(덕킹)로 요청하고, 음악 앱을 멈추지 않고 그 위에 겹쳐 냅니다(음악 소리를 얼마나 줄일지는 차의 오디오 정책을 따름). TTS는 아직 넣지 않았습니다. 피날레 뒤에는 무대가 열린 채 다음 곡으로 이어지고, 차량 상태는 무대를 닫을 때 복원합니다. 구현 내용은 [09](09-voice-reaction-plan.md) 5장 "흥 점수"에 있습니다. 2026-10-25에 "환호 바람"을 넣었습니다. 모든 등급의 피날레에서 0.5~2초에 풍량을 무대 시작 때보다 한 단 올렸다가 되돌립니다. 공조가 꺼진 차에서는 풍량 쓰기가 실패하고(앱은 공조 전원을 켜지 않음), 조명과 박수만으로 피날레를 합니다.

| 시점 | 연출 |
|---|---|
| 0초 | 음악 앱 소리를 잠시 줄이고(오디오 포커스 일시 획득), 박수와 환호 효과음 재생 |
| 0~3초 | 등급 색으로 앰비언트 조명 밝기를 2~3번 출렁이게 함 |
| 0.5~2초 | 풍량을 한 단계 올렸다가 되돌림 ("환호 바람") |
| 3초 | TTS: "92점! 오늘의 흥부자입니다" |
| 5초 | 조명, 공조, 음악 음량을 노래 시작 전 상태로 복원 |

### 주행 중 연출

- 박수 효과음을 1.5초 정도로 짧게 줄이고 음량 상한을 둡니다.
- 조명은 깜빡이지 않고 등급 색으로 천천히 바뀌었다가 돌아옵니다.
- 공조는 건드리지 않습니다.

### 점수 등급

세 단계로 나누되, 낮은 점수도 좋게 표현합니다. 가족과 아이가 함께 쓰는 앱이라 깎아내리는 표현은 다시 쓰지 않게 만들기 때문입니다.

| 등급 | 효과음 | 조명 |
|---|---|---|
| 기본 | 짧은 박수 | 흰색 |
| 좋음 | 박수와 환호 | 파란색이나 보라색 |
| 최고 | 기립박수, 휘파람, 팡파레 | 금색 (정차 중에는 실내등 반짝임 추가) |

### 동승자 박수 감지

정차 중에 동승자가 실제로 박수를 치면 마이크가 그 소리를 잡아서 조명 출렁임과 환호 효과음으로 키워 줍니다. 차가 관객 반응까지 받아 준다는 점에서 효과가 큽니다. 박수 소리는 짧고 날카로워서 노래보다 감지하기 쉽습니다.

## 기능 2. 2인 대결과 발표 모드

2026-10-23 구현(첫 단계): 화면의 "대결 시작"(무대가 열린 동안)이나 Gleo `START_BATTLE`("노래 대결하자")로 시작합니다. 무대가 닫혀 있으면 Gleo가 무대부터 엽니다.
- 진행: 운전석 한 곡, 조수석 한 곡의 턴제입니다. 10초 이상인 곡이 끝나면(틈을 듣거나 "곡 끝내기") 차례가 넘어가고, 각 곡의 흥 점수를 비교합니다. 10초보다 짧은 곡은 점수가 없으므로 차례도 넘어가지 않습니다. 차례인 사람의 색(운전석 파랑, 조수석 빨강)으로 앰비언트 조명을 바꿉니다. 운전석 차례가 끝날 때는 보통 곡처럼 피날레가 나옵니다.
- 곡 중간에 시작하면: 다른 앱의 음악이 나오고 지금 곡을 10초 이상 들었다면, 그 곡이 끝날 때까지 기다립니다. 그 곡은 혼자 부른 곡으로 점수와 피날레를 받고, 다음 곡부터 운전석 차례입니다. 기다리는 동안 화면에 "지금 곡이 끝나면 운전석부터 시작해요"와 "바로 시작"이 나옵니다. 음악이 나오지 않거나 곡을 들은 지 10초가 안 됐으면, 그때까지 들은 소리는 버리고 바로 운전석 차례를 시작합니다. 운전석 차례가 곡 중간부터 세어지면 앞부분이 빠져서 불리하기 때문입니다. Gleo는 무대가 실제로 어떻게 시작했는지 듣고 답합니다("지금 곡이 끝나면 대결을 시작해요" 또는 "운전석부터 한 곡 불러 주세요").
- 발표: 아래 "발표 모드 연출 순서"의 조명 부분을 넣었습니다(약 10초). 어둡게 1초 → 약 4초 동안 파랑·운전석 독서등과 빨강·조수석 독서등이 1초에서 0.35초 간격까지 점점 빠르게 번갈아(실제로는 프레임 단위로 올림해서 가장 짧을 때 약 0.38초) → 1초 정적 → 4초 동안 승자 색 최대 밝기, 승자 쪽 독서등과 시트 통풍(무승부는 보라, 양쪽) → 두 독서등과 승자 쪽 시트 통풍을 끄고 다른 층이 조명을 다시 맡습니다. 진 사람의 시트 통풍은 건드리지 않습니다. 가장 빠를 때도 한쪽이 켜진 뒤 다시 켜지기까지 0.7초 넘게 걸려서, 1초에 3번 깜빡임 기준 아래입니다.
- 발표가 끝난 뒤: 끈 독서등과 시트 통풍은 약 2초 동안 계속 요청해서, 안전 규칙이 한 번 막아도 다시 보냅니다(기어를 한 번 읽지 못하면 다음 읽기까지 최대 약 1.5초 동안 명령을 막음). 이 값은 무대를 닫을 때까지 꺼진 채로 있고, 무대를 닫으면 무대를 열기 전 값으로 돌아갑니다.
- 결과 화면: "승자는 조수석!"과 두 점수, "다음 곡에서 역전해 보세요!", "다시 대결", "확인". 무승부는 "무승부! 환상의 케미예요"입니다. 결과는 "확인"을 누르거나, 다음 곡의 점수가 나오거나, 새 무대를 열 때까지 남습니다.
- 도중에 바뀌는 경우: 차례 중에 다시 대결을 시작하면 처음부터 다시 합니다. 발표 중에 다시 시작하면 발표를 멈추고 켠 것을 끈 뒤 시작합니다. 대결 중에 무대를 닫으면 진행 중인 차례는 없어지고, 발표 중이었다면 결과를 바로 보여 줍니다. 주행을 시작하면 결과도 지웁니다.
- 효과음(2026-10-24): 좌우가 번갈아 켜지기 시작할 때 드럼롤(약 4초), 승자 조명이 켜질 때 팡파레(약 1.7초)를 냅니다. 드럼롤은 독서등과 함께 운전석(왼쪽)과 조수석(오른쪽)을 오가며 차례마다 조금씩 빨라지고(1.0배에서 1.15배), 팡파레는 승자 쪽에서 나옵니다(무승부는 가운데, 2026-10-24, 소리는 아직 귀로 확인하지 않음). 운전석 차례가 끝날 때의 피날레에는 박수가 나옵니다.
- MC 음성(2026-10-25): 발표가 시작될 때 "결과를 발표하겠습니다", 승자 조명이 켜지고 1.8초 뒤 팡파레가 끝날 때 "승자는 조수석! 53점입니다"(무승부는 "무승부! 환상의 케미예요")를 Pleos TextToSpeech SDK의 `ON_DEVICE` 모드로 말합니다(2026-10-31, 그 전에는 Android 표준 `TextToSpeech`). 차의 음성 서비스가 시작하지 못하면 화면 문구로 대신합니다. 에뮬레이터에서도 말합니다([05](05-emulator-findings.md) "Pleos TTS로 MC 음성 확인"). 승자 멘트는 팡파레에 묻히지 않게 위 표의 6초보다 조금 늦춰 팡파레가 끝날 때 말합니다.
- 온도 연출(2026-10-25): 승자 조명이 켜지는 4초 동안 승자 쪽(무승부는 양쪽) 온도 설정을 무대 시작 때보다 2도 낮췄다가, 발표가 끝나면 되돌립니다("시원한 축하"). 4초 안에 공기 온도가 크게 바뀌지는 않으므로, 차의 공조 화면에 보이는 설정값으로 전합니다. 무대가 열린 동안 사람이 직접 바꾼 온도는 발표가 끝날 때 그 값으로 돌아오고, 무대를 닫을 때는 무대 시작 때 값으로 복원됩니다. 성에 제거·와이퍼가 켜져 있으면 공조 연출처럼 건너뛰고(되돌리기도 그동안 기다림), 배터리가 낮으면 시작 때 값에서 더 멀어지는 설정은 막습니다. 에뮬레이터는 쓰기에 성공 응답만 하고 Virtual Console 값은 바뀌지 않았습니다([05](05-emulator-findings.md) "승자 쪽 온도 확인").
- 화면의 좌우 빛(2026-10-25): 발표 중에는 무대 글로우가 독서등이 켜진 쪽 가장자리를 그쪽 색으로 분명히 밝히고 반대쪽과 위아래를 어둡게 해서, 빛이 독서등과 함께 화면을 가로지릅니다. 무승부의 마무리에서는 왼쪽이 파랑, 오른쪽이 빨강으로 나뉩니다. 차가 제어를 허용하지 않아도 화면은 그대로 움직입니다.

### 시작

정차 중에 Seat API(`getCurrentSeatOccupancy`)로 운전석과 조수석에 모두 사람이 앉은 것이 감지되면 "두 분이 타셨네요. 대결해 보실래요?"라고 제안합니다.

2026-10-24 구현: 무대가 열려 있는 동안 앞좌석 두 자리를 3초마다 읽습니다. 대결 카드가 없을 때 두 자리 모두 사람이 앉아 있으면, 첫 화면 문구가 "두 분이 타셨네요. 노래 대결도 해 보세요"로 바뀌고 "대결 시작" 버튼이 채워진 모양으로 바뀝니다. 한 자리가 비거나 읽지 못하면 원래 문구로 돌아갑니다. 무대가 닫혀 있을 때는 읽지 않습니다. 무대를 여는 것이 먼저이고, 대결은 무대 위에서 시작하기 때문입니다. 에뮬레이터에서는 SDK 값이 콘솔·표준 속성과 반대라서 실차 확인이 필요합니다([05](05-emulator-findings.md) "착석 감지 확인").

### 진행

마이크가 하나라서 동시에 부르면 누가 불렀는지 구분할 수 없습니다. 그래서 왼쪽(운전석) 한 곡, 오른쪽(조수석) 한 곡의 턴제로 진행합니다. 왼쪽은 파랑, 오른쪽은 빨강으로 색을 정하고, 차례가 된 사람의 색으로 조명을 바꿉니다.

### 좌우 연출 레이어

앰비언트 조명은 실내 전체가 한 영역이라서 다섯 가지를 겹칩니다.
1. **소리**: 드럼롤을 왼쪽과 오른쪽 스피커로 번갈아 보냅니다. 차량 API가 필요 없어서 가장 확실한 방법입니다.
2. **독서등**: 좌석별로 켤 수 있으므로(`setReadingLightSwitch`, 1열 좌·우) 좌우 독서등을 번갈아 켭니다. 정차 중에만 씁니다.
3. **색**: 앰비언트 조명 전체를 파랑과 빨강으로 번갈아 바꿉니다(`setAmbientLightBrightnessColor`).
4. **화면**: 디스플레이에서 빛이 좌우로 오가는 애니메이션을 보여 줍니다. 정차 중이라 화면 연출이 허용됩니다.
5. **시트·온도**: 시트 통풍(`setHvacSeatVentilation`)과 온도(`setHvacTemperature`)는 좌우가 따로라서, 승자 쪽에 "시원한 축하"를 줍니다.

### 발표 모드 연출 순서

| 시점 | 연출 |
|---|---|
| 0~1초 | 앰비언트 밝기를 최저로 낮추고, TTS: "결과를 발표하겠습니다" |
| 1~5초 | 드럼롤 소리가 좌우 스피커를 오가고, 조명 색이 파랑과 빨강으로 교대하고, 화면의 빛과 점수판도 좌우로 오감. 교대 간격은 1초에서 0.35초로 점점 빨라짐(한쪽이 켜진 뒤 다시 켜지기까지 0.7초 이상) |
| 5~6초 | 소리를 멈추고 조명을 최저로 낮춰 1초 동안 정적 |
| 6초 | 승자 색으로 조명 최대 밝기, 승자 쪽 스피커에서 팡파레 시작, 화면 점수판에 아직 가려 둔 점수가 나오고 승자 쪽이 커짐 |
| 6~10초 | 승자 쪽 시트 통풍과 온도 2도 낮춤, 팡파레가 끝나면(약 7.8초) TTS: "승자는 조수석! 88점입니다" |
| 10초 이후 | 화면에 "다음 곡에서 역전해 보세요!"(무승부는 없음)와 "다시 대결"·"확인" 버튼, 독서등과 시트 통풍을 끄고 온도는 무대 시작 때 값으로 되돌림. 나머지 차량 상태는 무대를 닫을 때 복원 |

- 무승부가 나오면 화면을 두 색으로 나누고 "환상의 케미"라고 발표합니다.
- 실제 차량에서 색 전환이 느리게 반응하면 색 교대 횟수를 줄이고, 소리와 화면으로 속도감을 냅니다.

### 벌칙 열선은 제거

1차 검토에 있던 벌칙 열선은 뺍니다. 아이나 노약자에게 화상이나 불쾌감을 줄 수 있고, 낮은 온도로 30초만 켜면 체감도 거의 되지 않습니다. 진 사람에게 벌칙을 주기보다 이긴 사람에게 보상을 주는 구조가 다시 쓰고 싶은 경험을 만듭니다.

## 사업화 리스크 검토

법률 관련 내용은 공개된 조문과 기사를 바탕으로 정리했으며, 사업화 전에는 전문가 검토가 필요합니다.

| 영역 | 위험 | 결정 |
|---|---|---|
| 가사·반주 제공, 노래방 업체 정식 반주 | 저작권 사용료, 권리자 협상 부담 | 핵심 사업 모델에서 제외하고 장기 옵션으로만 언급 |
| 음정 채점 | 기준 멜로디 데이터 저장이 복제에 해당할 소지 | 흥 점수로 대체 |
| 노래 녹음·저장·SNS 공유 | 음원 저작권, 동승자 음성 | 녹음 기능 제거, 점수 카드 이미지만 공유 |
| 음성을 서버로 보내 분석하거나 곡 인식 | 통신비밀보호법은 공개되지 않은 타인 간 대화를 전자장치로 녹음·청취하는 행위를 금지함. 음성은 개인정보이기도 함 | 모든 분석을 차량 안에서 처리하고, 오디오는 저장·전송하지 않음. 마이크는 노래하는 동안에만 켜고 화면에 켜짐 상태를 표시 |
| 지역별 랭킹 | 위치정보법 (위치기반서비스사업 신고, 개인위치정보 동의) | 위치 기반 랭킹 제거. 첫 버전은 서버 없이 "우리 차 기록"만 저장 |
| 주행 중 파티·대결 | 도로교통법 제49조 (승객이 안전운전에 현저히 장해가 될 정도로 소란을 피우게 두고 운행하는 행위 금지, 운전 중 운전자가 볼 수 있는 위치에 영상 표시 금지), Pleos 가이드의 게임 유도 금지 | 주행 중에는 드라이브 연출만 허용. 대결, 발표, 시각화는 정차 중에만 사용. "파티"라는 표현은 홍보에 쓰지 않음 |
| 파티카 B2B | 음주와 소란을 연상시켜 브랜드 이미지에 부담 | 제거. 렌터카는 "가족 여행 테마" 정도로만 제안 |
| 정차 중 장시간 콘서트 | 내연기관 차량의 공회전 (지자체 공회전 제한 조례, 밀폐된 공간의 배기가스), 배터리 방전 | 충전 중인 EV를 우선 타깃으로 잡음. 내연기관은 사용 시간 제한과 경고, EV는 배터리 잔량 하한 설정 |
| 공조 연출 | 성에 제거를 방해하면 시야 확보에 문제 | 성에 제거나 와이퍼가 작동 중이면 공조 연출 생략. 끝나면 원래 상태로 복원 |
| 효과음 | 갑작스러운 큰 소리로 운전자가 놀라거나 사이렌을 못 들을 수 있음 | 주행 중 효과음은 음량 상한을 두고 짧게 재생 |
| 유료 테마 팩 | Pleos App Market의 인앱 결제 지원 여부를 확인하지 못함 | 확인되기 전까지 핵심 수익원에서 제외 |
| 아티스트·아이돌 콜라보 테마 | 퍼블리시티권, 상표권 | 제휴 계약 전에는 사용하지 않음 |

## 다듬은 사업 모델

- **타깃**: 1순위는 충전을 기다리는 EV 운전자와 가족 동승자, 2순위는 커플이나 친구끼리의 드라이브입니다.
- **현대차그룹 기본 탑재**: "Pleos 차량에서만 되는 경험"으로 차량 상품성을 높이는 기능입니다.
- **충전 사업자 제휴**: 현대차그룹의 충전 브랜드 E-pit과 묶어 "충전하는 동안 콘서트"를 제안합니다. 충전 대기 시간을 즐거운 시간으로 바꾸는 콘텐츠입니다.
- **음원 앱 제휴**: 멜론이 이미 Pleos App Market에 들어와 있습니다. 멜론에서 곡 정보와 후렴 구간 정보를 받으면 연출 정확도가 높아지고, 멜론은 차 안에서 머무는 시간이 늘어납니다. 서로 이익이 되는 구조입니다.
- **리텐션 장치**: 시즌 테마(여름휴가, 크리스마스)를 무료로 제공하고, 가족 누적 흥 점수와 칭호, 대결 전적을 차 안에 기록합니다.
- **장기 옵션**: 노래방 업체와 제휴한 정식 반주 모드는 확장 계획에만 넣습니다.

## 남은 확인 사항

1. ~~조명의 좌우 영역 지원 여부~~: 에뮬레이터에서는 앰비언트가 영역 하나, 독서등·온도·시트 통풍은 좌우 분리 (2026-10-21 확인)
2. 마이크 원본 오디오 접근: 에뮬레이터에서 가능 (2026-10-21 확인). 에코 제거(AEC)는 실차 확인 필요
3. 다른 앱의 재생 정보(트랙 변경) 접근 가능 여부
4. 색 전환 속도: 쓰기 응답은 150ms 간격에서도 실패 없음. 실제 조명 반응 속도는 실차 확인 필요
5. Pleos App Market의 인앱 결제 지원 여부
6. 카테고리는 엔터테인먼트로 정함 (2026-10-22, 음악·오디오는 음원 재생이 주 기능인 앱만 받음). 대결 기능 때문에 "게임"(미디어 앱)으로 분류되는지
7. NaviHelper로 도착 예정 시간을 받아올 수 있는지 (셋리스트 기능)
8. Vehicle Control SDK가 "Coming Soon" 상태인데, 실차 배포 시점에 제어 기능이 열리는지 ([11](11-no-control-plan.md) 9장)
